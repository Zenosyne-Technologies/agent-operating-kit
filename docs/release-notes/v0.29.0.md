# v0.29.0 — visual capture, made executable and swept across the whole project

v0.28.0 shipped the visual validator's rules and lifecycle slot; this release makes its **capture path executable and verifies it against a real UI**, and adds the whole-project sweep. Everything is a capability consumers adopt or ignore — nothing existing breaks.

**The capture procedure is now executable (AOS-126).** The guide's capture section named a procedure in prose; it now names the concrete browser-pane tools a validator actually calls — `preview_start` (a `url`, or a `name` from `.claude/launch.json`), `navigate` per surface, `resize_window` to each breakpoint (`desktop`/`mobile` presets, `colorScheme: dark` where themed), and `computer` screenshot saving each PNG as evidence. Each rung of the degradation ladder is now tied to an **observable browser outcome**: `preview_start`/`navigate` failing (a dead port) is the NO-RUNTIME signal; a surface that resolves to a non-200/error page is UNREACHABLE (validate the rest, never block the pass).

**A Playwright fallback (AOS-127).** When a project already scripts E2E, the validator may capture via Playwright (`browser_navigate` / `browser_resize` / `browser_take_screenshot`) instead of the pane, and read `browser_console_messages` for console/network errors — signal a screenshot alone misses. It is a fallback with an explicit selection rule; the browser pane stays the default.

**A whole-project visual sweep (AOS-129).** A new `/marvin:play` scenario, `visual-sweep`, runs under the existing bounded-execution contract: enumerate every surface from the screen catalog, fan out `marvin:validator-visual` across slices (hard cap 4 per round, like `research-deep`), and aggregate the per-surface findings into ONE whole-project design report in `.docs/reports/` — the cross-surface view a per-page pass cannot see (shared-component drift, type/colour-scale coherence). It exits honestly when the tooling is absent or nothing runs. It auto-registers in the `/marvin:play` menu.

**Verified live.** The capture path and the sweep were exercised against a purpose-built 3-screen scratch UI: the browser-pane matrix (desktop/mobile × light/dark) caught a low-contrast CTA, a mobile layout overflow, and a dark-mode-only hardcoded card; both degradation rungs fired as specified; and a dispatched validator sub-agent — with full browser-pane access — caught a real, unplanted nav-misalignment defect fresh-eyes, then those findings aggregated into one design report.
