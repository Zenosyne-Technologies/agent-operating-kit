# v0.39.0 — host tidying and ticket-filing standards

**Consumers act once:** run `claude plugin update marvin`, follow the update procedure the SessionStart notice prints (`upgrades/v0.39.0.md`), then label or remove your existing Docker resources by hand.

**Docker tidying.** Every Docker resource an agent creates carries four labels: `marvin.project`, `marvin.checkout`, `marvin.owner` and `marvin.lifetime`. The new `.marvin/agents/tidying.md` owns the rules: naming, throwaway versus keep, who removes what, and the handoff listing. The plugin's Docker sweep runs at session start and in `/marvin:clean-worktrees`; it removes throwaway containers, networks, volumes and images whose owner worktree is gone, and keeps a resource when any of seven guards holds (D0 another checkout, D1 not throwaway, D2 main-owned or no owner, D3 an owner name that fails validation, D4 the worktree still exists, D5 a container still running, D6 docker refused the removal), plus D7: an image with several tags, which it never untags. A Docker lint advises on unlabelled resources and on compose stacks without a project name. Resources created before this upgrade carry no labels and are never swept.

**Throwaway databases.** A database snapshot, copy or instance made for a sandbox, test run or agent worktree runs with binary logging off. The Docker lint advises when a throwaway MySQL or MariaDB container is started with it on, and never touches the project's real databases.

**Ticket-filing standards.** Label registry v1.5.0 requires `size:` on every non-epic item at filing, treats a size or severity written only in prose as unlabelled, and fixes the severity spelling (`sev4-low`). The ticket lint checks tracker writes to the project's own tracker (Jira, Linear, GitHub, Local) before they happen: with `ticket_lint: block` (the default) a violation is denied, with `advise` it is a note, with `off` nothing runs. A `gh` command it cannot parse with certainty only gets advice. The tracker intake brief gains an audit of open items: it reports by default, and the upgrade asks one yes/no before backfilling the flagged items. AOS-219 was a Jira-only backfill of existing items with no commits, so it is named here, not in scope.
