# v0.35.0 — reports move to .marvin/reports/

**Consumers act once:** run `claude plugin update marvin`, then `/marvin:upgrade-agent-os`. If it stops because something blocks the move, clear what it names and run it again (`upgrades/v0.35.0.md`).

Reports are what Marvin produces about its own work — stats snapshots, digests, milestone close-outs, install and upgrade reports. They lived in the project's documentation estate, `.docs/reports/`, beside the handbooks written for humans. They now live with Marvin's machinery in `.marvin/reports/`, still committed as project record.

**A tested move, not a checklist.** The upgrade runs `scripts/migrate-v0.35.0.sh` right after the one-time split question: every file under `.docs/reports/` moves to the same path under `.marvin/reports/`, staged by exact path and committed as its own step. It refuses untracked files, collisions, symlinks and unsafe repository states before anything moves — a collision refuses the whole move, never part of it — and rolls back to the last commit if anything fails midway. Each of its guards is pinned by a test that fails when the guard is removed.

**A blocked move stops the upgrade.** Whatever the script refuses, the upgrade stops there — it commits only its report naming the blocker, keeps the old version stamp, and changes nothing else — so a project is never left with reports split between the two folders. Clear the blocker and re-run.
