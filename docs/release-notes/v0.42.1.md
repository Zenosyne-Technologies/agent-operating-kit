# v0.42.1 — Fleet-mode follow-ups and two small fixes

**Consumers act once.**
1. Run `claude plugin update marvin`, then `/marvin:upgrade-agent-os` in one session.
2. If a free-text `PROJECT-INFO.md` value holds `: ` unquoted, run `/marvin:project-info` (`upgrades/v0.42.1.md`).

**Why.** The v0.41.0 fleet-mode release deferred its minor findings as sev4 follow-ups, and two defects outside fleet mode turned up in the same work: an unquoted `brief:` made `PROJECT-INFO.md` invalid YAML whenever the user's words contained `: `, and `test-docker-lint.sh` failed now and then with no code change.

**What changed.**
- **PROJECT-INFO quoting (AOS-246, sev3).** The free-text keys are double-quoted in the template; the install and `project-info` skills escape `\` and `"` and repair an unquoted value; the new `frontmatter-quoting` gate (23rd check) holds the template to it.
- **Flake (AOS-247).** Both lint suites' "never writes" snapshot used `ls -laR`, which also lists `..`, the shared temp directory. Any concurrent `mktemp` changed it. The snapshot now covers only the suite's own directory; 45 parallel runs passed where 7 of 90 had failed.
- **Fleet tests (AOS-248).** The role-marker suite checks stderr after every call, every malformed epic key, strict `role=` parsing and the 4 KiB cap (two new mutations); the compaction counters pin their sidechain and symlink behaviour; the sweep is shown to keep a `--reason`-locked worktree.
- **Hook limits (AOS-249).** The context hook's header records what was decided not to fix: restart threshold unscaled, `autoCompactEnabled:false` undetected, bounded repeats, one `git rev-parse` per call.
- **Gate (AOS-250).** `fleet-pairs` also requires the two fleet guides' `E-*` tag sets to be equal.
- **Guides (AOS-251, AOS-252).** `git-strategy.md` scopes the `develop` row and branch death for fleet mode; restatements of the branch cut and the lock command are gone; a board item without a `FLEET-Q<n>` is never relayed; the master's handoff goes to the program plan's **Handoff** section; the MEMORY.md-before-compaction rule carries the fleet-child exception.
- **Child and stop (AOS-253, AOS-254, AOS-255, AOS-256).** Resolved-path compare for `CLAUDE_PROJECT_DIR`; a missing master marker means the fleet stopped; a child told the fleet is stopping hands off; stop lists the running children, accepts a squash/rebase-merged epic with the architect's confirmation, and the Local refusal keys on `pm_tool`; resume rewrites a missing child marker; `/marvin:info` reports a fleet marker and flags a stale master one.

**Not done, by decision.** AOS-255 reports the stale marker through `/marvin:info` only (no SessionStart line); AOS-249's four items are documented, not changed.

**Acceptance.**
- Gates: all 17 test suites green (hook-lib 275, worktree-sweep 225, the rest unchanged); `validate-kit` 23/23, each new check mutation-tested.
- The ticket text of AOS-253 to AOS-256 was written against v0.41.0; the guide wording was re-read against the v0.42.0 files before editing.

This note's `scope:` was derived over `v0.42.0..HEAD`, non-merge commits only; the container epic AOS-242 is excluded.
