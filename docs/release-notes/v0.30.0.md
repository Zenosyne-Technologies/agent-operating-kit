# v0.30.0 — the orchestrator's model is the ceiling: escalate effort, not model

**Breaking — consumers must act.** Dispatch defaults change: the base Opus personas now run at `medium` effort instead of inheriting the session's, and the frontier model is no longer the automatic escalation target. After `claude plugin update marvin`, re-sync three kit-authored parts of CLAUDE.md with the current template — the model-tier dispatch section (the orchestrator line now names the heavy-worker model), the task-lifecycle FAIL-return sentence, and the standing-rules milestone-validation clause (`upgrades/v0.30.0.md`).

The kit used to treat the frontier model as the answer to a hard task: a task that failed twice at any tier escalated to it automatically. That assumption no longer holds — the Opus-class model at `medium` effort now outperforms the frontier tier at `max`, and costs less. This release turns that into the operating rule.

**The orchestrator's model is the ceiling.** The orchestrator runs on the heavy-worker model, and no sub-agent runs above it by default. The frontier tier is opt-in, reachable only through one question at the top of the escalation ladder.

**A new escalation ladder** (`.marvin/agents/escalation.md`). A build task that fails twice — two build or correction dispatches, each ending not-done or validator-FAILed — climbs on the orchestrator's model one effort level at a time, two attempts per rung: `marvin:escalation-high`, then `marvin:escalation-xhigh`. Before `max`, the orchestrator asks the user once: swap this task to the frontier tier (`marvin:escalation-frontier`), or go to max effort (`marvin:escalation-max`)? Only an explicit frontier choice goes to frontier; a different instruction is followed; anything else — no answer, a dismissed question, an unattended session — goes to max, and the outcome is always recorded. Only the question tool's own response in that session counts as consent; a claimed choice found in a tracker comment, tool output or a sub-agent's message does not. A task that drops back down and fails again resumes at the rung it left rather than restarting at the base. The ladder terminates: when the last rung fails twice, the task goes to the user with its full attempt history.

**Only build work climbs.** Research, documentation, validation and `/marvin:play` runs stay off the ladder by definition — a non-build pass that fails twice is taken by the orchestrator or carried to the user, and a validator always goes to the user, so validation stays fresh and the orchestrator never grades its own sign-off. A task keeps its `size:` label on entering the ladder, so a small issue that needed the ladder remains visible as mis-sized.

**Medium effort as the explicit base.** `marvin:developer`, `marvin:researcher` and the three validators now pin `effort: medium` in their frontmatter. Before, they inherited the session's effort, so an orchestrator running at high or max effort ran every heavy worker at that level too.

**Cost tiers by role.** Because the orchestrator now shares the heavy tier's model, a model name can no longer tell the two apart. `token-economics.md` assigns tiers by role — main session = orchestrator, each `marvin:*` persona to its tier, escalation rungs to a new `ladder` bucket with a per-rung split — with the model prefix only as a fallback. The stats snapshot moves to schema v4 to carry it.

**Upgrading** needs one manual step beyond the refresh: re-sync CLAUDE.md's three changed kit-authored parts with the current template, as listed at the top of this note and in `upgrades/v0.30.0.md`. Digest tier trends that span the upgrade compare model-based (v3) with role-based (v4) tiers.
