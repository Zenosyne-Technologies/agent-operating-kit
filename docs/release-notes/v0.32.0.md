# v0.32.0 — Marvin targets a declared model set

**Consumers must act.** After `claude plugin update marvin`, run `/marvin:upgrade-agent-os`, then re-sync two lines of CLAUDE.md's *Model-tier dispatch* section and its concrete model names with the new profile (`upgrades/v0.32.0.md`).

Marvin was written model-generic: tier names everywhere, concrete models chosen at install. That stopped holding with Opus 5.5, whose max effort now outperforms the frontier tier (Fable 5.1) for far less cost — a rule written for "any frontier model" gets that wrong. From this version on, each Marvin release is built and validated for a declared model set, and model-specific rules live in one place.

**The model profile.** `.marvin/agents/model-profile.md` is the single owner of the version's model set and its model-specific rules: orchestrator Opus 5.5 at medium effort (high when a task needs it), heavy worker Opus 5.5, small worker Sonnet 5, micro Haiku 4.5, frontier Fable 5.1 opt-in only. Every other guide keeps tier names and cites it. It is kit-owned: an upgrade replaces a customised copy (keeping a backup), and running other models is unsupported — Marvin shows one callout when the session's model differs, and never blocks.

**The max gate recommends max.** When a stuck build task reaches the top of the effort ladder, the question now offers max effort on the orchestrator's model first, as the recommended choice, and the frontier tier second, as the costlier alternative. Everything else about the gate is unchanged.

**Install reads the profile.** The install skill takes its tier-to-model names from the plugin's profile instead of re-checking at install time. A new `validate-kit` check (`model-names`, the 13th) fails any template other than the profile that names a model.

Later versions will add profiles for other model sets.
