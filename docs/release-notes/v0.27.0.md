# v0.27.0 — a brief-first greenfield interview and a branded attribution option

Two install-flow improvements. Both affect **new installs only**; existing installs are untouched (the interview runs at install time, and PROJECT-INFO/settings are never overwritten on upgrade).

**Brief-first greenfield interview (AOS-117).** The greenfield interview used to ask target audience, size and app type, then propose a tech stack — with no idea what the user was building, so the stack was suggested blind. It now asks a short **project brief ("what are you building?") FIRST**, and the stack step reasons from that brief. The brief is persisted as a new `brief:` field in `.marvin/PROJECT-INFO.md` (18 frontmatter keys now), and the `project-info` skill knows the field on both create and validate. Only the greenfield path changes; brownfield discovery is unchanged.

**A third attribution option (AOS-118).** The install's attribution question was a two-way choice (keep the default AI attribution, or disable it). It now offers a **third option — "Emprove Marvin (Claude)"** — a branded commit/PR trailer, so agent-made commits can be attributed to the Marvin operating system. The three outcomes: keep-default skips the settings file (Claude Code's own default applies), disable writes empty attribution, and the branded option writes the "Emprove Marvin (Claude)" trailer into `settings.json` and the CLAUDE.md attribution line.
