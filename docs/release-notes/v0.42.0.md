# v0.42.0 — Session clean-up fix (session worktrees and run state survive clean-up)

**Consumers act once.**
1. Pre-set `ticket_lint`, `worktree_sweep` and `docker_lint` if you want other than the defaults.
2. Run `claude plugin update marvin`, then `/marvin:upgrade-agent-os` in one session.
3. Restart the other open sessions.
4. Run the upgrade again once the sessions it deferred have finished (`upgrades/v0.42.0.md`).

**Why.** Two architects lost live state. The v0.37 sweep treated every worktree under `.claude/worktrees/` as disposable. A desktop session that had made no commit of its own and had been quiet for 15 minutes passed every guard, and another session's sweep removed it. The orchestrator's git-ignored ledger, briefs and run reports lived inside that worktree and went with it (CAL-184; Erik's questions).

**Host facts (verified on CLI 2.1.289 and the desktop app).**
- SessionEnd fires with reason `other` on the app's 15-minute idle pause as well as on archive. A hook cannot tell the two apart, so the kit uses no session lock.
- `/clear` changes `session_id`; resume keeps it.
- The app's archive pools a worktree and keeps its ignored files.
- The app's built-in write guard blocks Write and Edit into the main checkout from worktree sessions and their sub-agents, but not Bash.
- SubagentStop fires before Claude Code removes a clean agent worktree. Its `cwd` is `.claude/worktrees/agent-<agent_id>`.

**What changed.**
- **Sweep scope (AOS-223).**
  - A `marvin-owned` marker is written at SubagentStop for exactly the agent's own isolated worktree. A worktree made by hand is marked with `/marvin:clean-worktrees --mark`, which refuses one older than 60 minutes.
  - The sweep considers only marked worktrees. Everything else is the app's.
  - G8 keeps a worktree whose ignored `.env*` differs from, or is missing in, the main checkout. It does not look inside wholly ignored folders.
  - G9 keeps a worktree whose carried run file is not identical in the project.
  - `--at-risk` reports both, for every worktree.
- **Run state (AOS-224).** Writers write in their own checkout. Hooks carry the files to `<project>/.marvin/runs/<UTC>-<session_id>/<KEY|adhoc>/`, which is the only copy readers use:
  - SessionStart creates the folder, the `.gitignore` and seeds the local copies.
  - PostToolUse copies the orchestrator's writes; a ledger only when it extends the project copy.
  - SubagentStop copies brief-named reports, with clash sidecars.
  - Stop catches up a Bash-written ledger or build brief.

  Ledgers chain across sessions (`chain:` first line). The prune follows the new layout. The key rule admits single-letter prefixes and bare GitHub issue numbers.
- **Settings (AOS-225, AOS-228, AOS-230).**
  - `worktree_sweep: on | check | off`; absent = check.
  - An absent `ticket_lint` means advise.
  - `docker_lint: advise | off`.
  - A missing mode key never enforces, and hooks never gate on the kit version.
- **Recovery (AOS-226).** `session-recovery.md`, with the recreate and prune recipe in `worktrees.md` *Where*.
- **Windows (AOS-227).** `mh_path` decodes and normalises hook paths. There is a `windows-latest` CI job, non-blocking until its first green run, plus LF `.gitattributes` and a README section.
- **Update gate (AOS-229).** U3 needs five bold points and U4 a heading after the last status line, in any language. English stays the documented default.
- **Precedence (AOS-231).** Only selective staging and the tagging authority stay gated. The branch model, merge style and push cadence are project-refinable.
- **Upgrade readiness (AOS-237).** Step 6b runs on every upgrade. It probes first, and only when there is run state to move does it ask which sessions are open, defer them, run `marvin-runs-migrate.sh`, report at-risk files and both sweeps' `--check` output, and ask for a restart.
