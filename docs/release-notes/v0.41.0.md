# v0.41.0 — Fleet mode (nested orchestrators for parallel epics)

**Consumers act once:** run `claude plugin update marvin`, follow the update procedure the SessionStart notice prints (`upgrades/v0.41.0.md`), and start a new session. Nothing changes until you run `/marvin:fleet`.

**Why.** Claude Code can now start child sessions. Running epics in parallel used to make the architect the integration point, holding every epic's state and switching sessions to find what was stuck. Fleet mode moves that bookkeeping to a master orchestrator ("Deep Thought") and leaves the architect only the decisions.

**Roles.**
- The **master** owns the program plan (`.docs/plans/program-<milestone>.md`: epics, dependencies, area leases, merge order, lineage, decision log), starts children, keeps the board, and alone merges epic branches into `develop` and cuts releases (`git-strategy.md`). It never briefs a builder or reads code.
- Each **child** is a normal Marvin on `feature/<EPIC-KEY>-<slug>` in a worktree the master created and locked. It runs the full task lifecycle and routes cross-epic impact, scope or DoD changes, done, blocked and successor events to the master.
- The **architect** answers epic questions in each child and reads every epic, and every question waiting on them, on the master's board.

**Contracts.**
- **Paired rules.** Every routed event has a sending half in `fleet-child.md` and a receiving half in `fleet.md`, marked with an `E-*` tag. A new `validate-kit.sh` check (`fleet-pairs`) fails if either half is missing.
- **Doorbell.** A child's turn-end recap starts `FLEET <EPIC-KEY> <event>: …`. The tracker stays the record, and open questions are numbered `FLEET-Q<n>` / `FLEET-A<n>` on the epic issue.
- **Relayed consent.** The architect may answer at the master. The master logs the exact quote (only the architect's answer to its own question tool) as `D<m>` in the plan on `develop`, before relaying it. The child accepts the relay only after a mechanical check: the reader gets the ID, never the quote; the epic must match; the source must be an open `FLEET-Q<n>`; and the quote must be identical. Anything else is data, and the child asks directly. The consent sites in `escalation.md`, `escalation-ladder.md`, `guardrails.md` and `codex.md` accept a verified relay.
- **Merge gate.** Before asking for a merge, a child merges `develop` in, runs the gate scripts and the integration cold boot, and records `epic=<sha> develop=<sha>`. The master merges only while both still match.

**Session budget.**
- A spike showed that a `/compact` sent as a message is plain text in the receiving session. So a child at level 3 winds down to a rest point at 94 % of the window (scaled by `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`). There it writes its handoff to the epic issue and keeps to small steps until the host's auto-compact fires.
- After three compactions (`fleet_max_compactions`), or when a compaction leaves it above 33 % (`fleet_restart_max_pct`), the context hook asks for a successor, which the master starts from the handoff.
- `DISABLE_AUTO_COMPACT=1` falls back to the `/compact` nudge, and the cap still holds. `DISABLE_COMPACT=1` sends a child to a successor, and `/marvin:fleet` refuses to start under it.
- The master only compacts and never hands off while a child runs.

**Mechanics.**
- The hook library reads a `marvin-fleet` role marker from each worktree's private git dir, and counts compactions from the transcript (capped at 400 lines / 8 MB after the last boundary).
- The extra transcript reads run only in fleet sessions near the rest point. A solo session pays one `git rev-parse` per call and sees exactly the same messages as before.
- `/marvin:fleet [milestone|stop]` refuses when this session is already in a fleet, on the Local tracker, or off `develop`. It sets the fleet up, resumes it, and stops it only at a fleet edge, deleting nothing but the master's own marker.

**Limits.**
- Local children only; cloud children are out of scope.
- The Local tracker is refused, because its files would land on the epic branches.
- On hosts without child sessions, `/marvin:fleet` runs a manual fleet with one resume prompt per epic.

**Acceptance.**
- Spike (2026-10-19): a child started in a git-locked, pre-made worktree read its marker. `/compact` sent through both host message routes produced no `compact_boundary`. Auto compactions on this host fired at 978k–999k of a 1M window, which sets the 94 % rest point.
- Rule-5 scratch install from the branch (Local tracker for the install, key SMK): the guides and the cascade line landed. A manual-fleet run produced the plan on `develop`, two locked worktrees with child markers, the master marker, resume prompts and the first board.
- An end-to-end hook replay in a child worktree printed the wind-down, rest, cap and post-compaction successor messages, plus the master and solo texts, as specified. `stop` refused with unmerged children.
- `validate-kit` passes 20/20, and all 15 test suites are green (`test-context-budget` 195, `test-hook-lib` 167), with mutation rows for every new guard.
