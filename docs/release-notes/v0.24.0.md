# v0.24.0 — installs that interview and scaffold, docs that stand alone, and a sharper Marvin

**A greenfield install now interviews instead of guessing.** Until now install assumed an existing codebase and read the stack and layout off the repo — which leaves nothing to read in an empty project. This release splits install into greenfield and brownfield: a repo carrying no source (only docs, config, git metadata, or bare build manifests and lockfiles) takes an interview path — audience (personal · intra-team · restricted-public · public), estimated size, application type, and tech stack, with a stack advisory that offers a few coherent, well-supported combinations and a "you choose" option rather than reaching for something niche. The answers become PROJECT-INFO facts (`audience`, `project_size`, `app_type`, `stack`). A brownfield repo keeps the old code-discovery path untouched.

**And it can scaffold.** As the last step, a greenfield install with a chosen stack may scaffold it — which is not a side effect but tracked work: it plans the baseline documents first, creates "Milestone 0 — scaffolding and installing project dependencies" in the tracker, and runs the scaffold and dependency install as normal-lifecycle tasks under it. A brownfield or "files only" install skips scaffolding and proceeds straight to the commit.

**The documentation estate now stands on its own.** `.docs/` used to point into `.marvin/` for its authoring rules — which meant a project that wanted to hand off or expose its documentation could not do so without exposing the agent machinery. The dependency is now one-way: a `.marvin/` guide may point into `.docs/`, but nothing under `.docs/` references `.marvin/` or names the orchestrator. The estate states its own navigation and header conventions at its root, and the authoring standard stays reachable for an agent through the cascade rather than through a pointer embedded in a document. A new static-gate check (`docs-self-contained`) fails the build if the coupling is ever reintroduced.

**Marvin trusts nothing unproven.** The orchestrator persona leans into a productive, work-directed skepticism: it assumes unverified work is broken until the evidence says otherwise, and treats a "done", a passing check, or a number from nowhere as a claim to falsify rather than a fact to accept. The pessimism is aimed at the work and guarded against paralysis and self-pity — it catches defects early and moves the instant the evidence lands. It is the same stance the kit's validators already run on, now stated in the persona that dispatches them.

**For consumers**: `upgrades/v0.24.0.md` is the whole upgrade. Nothing moves or is renamed, so this release ships no migration script; the kit-owned refresh brings the one-way-dependency rule in `document-standard.md`, and the interview, scaffolding, self-contained seeds and persona nudge are adopted by new installs — existing projects are unaffected unless they choose to adopt them.
