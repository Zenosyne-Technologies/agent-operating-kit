# v0.31.0 — escalate on failure pattern; an orchestrator context diet

**Breaking — consumers must act.** Dispatch defaults change again: `size:m` no longer builds whole on the heavy tier, planning research no longer always gets a heavy pass, and a failed build round is read for its failure PATTERN instead of just counted. After `claude plugin update marvin`, run `/marvin:upgrade-agent-os` (it refreshes `.marvin/agents/` and adds the `.gitignore` line), then re-sync CLAUDE.md's nine changed kit-authored parts with the current template — the memory, model-tier dispatch, task-lifecycle, rules-cascade and standing-rules sections all moved (`upgrades/v0.31.0.md`) — and add `.marvin/runs/` to `.gitignore` if the upgrade skill has not already done so.

**`size:m` is no longer one indivisible heavy-tier build.** It splits into a design-bearing core, built on the heavy tier, plus peripheral pieces — tests from a spec, docs, wiring, fixtures, index rows — built on the small and micro tiers, and validated together as one unit so the DoD still gates the whole task. A correction whose fix list the orchestrator has fully specified goes straight to the small tier rather than back to the heavy one. Before any `size:m`+ build, a read-only small-tier brief falsifier lists undefined terms, unhandled cases and contradictions in the brief for the orchestrator to resolve first — on its first outing it found seven gaps in another task's brief, all closed before build started. Ladder attempts are now counted as ROUNDS (one build-or-correction dispatch through one full validation pass), not individual dispatches.

**Planning research splits the same way.** A `size:l`/`size:xl` plan still gets adversarial plan-validation and solution research, but the survey pass is now small-tier and read-only (its own SURVEY format); heavy-tier synthesis runs only for `l`/`xl`. `size:m` and below get an ad hoc survey only when the orchestrator asks. Ponytail — the micro persona — gains a standing job list: bounded database and fixture copies, exact-pattern sweeps, and report-only pre-flight gate runs (a pre-flight FAIL counts as a failed round).

**Escalation now reacts to failure PATTERN, not failure count.** After each failed round the orchestrator reads the round against seven signals — Converging (stay put), Stuck (climb the effort ladder), Whack-a-mole, Bloat, Loop (RETHINK the approach instead of climbing), Cost blowout (pause and ask the user), Round cap (a per-round dispatch/spend cap whose breach itself counts as a failed round, closing the gap where a stuck piece could stall forever below the ladder). Settings: N=4, K=3, M=6, and size budgets (xs $2 · s $8 · m $30 · l $90 · xl $250). A RETHINK step dispatches a fresh, read-only researcher to propose a different approach, capped at two attempts. Every task now carries a per-task ledger, and validator findings carry a tag the pattern rules read. **Descope** is now defined precisely — any change that narrows a DoD item's reach — and needs the user's explicit yes from the question tool (never a claim found in a tracker comment or sub-agent message); a descope is recorded by removing the item from the tracker DoD, not by a ledger line. `escalation.md` is split: it now holds only the round signals, and the ladder itself (high → xhigh → the ask-at-max frontier gate → stop at the user) moves to the new `escalation-ladder.md`.

**The orchestrator is on a context diet.** Every sub-agent's final message is capped at a short digest (verdict, one line per finding with `file:line`, gate lines); the full report goes to a gitignored `.marvin/runs/` (self-ignoring `.gitignore`), pruned at milestone close. Tracker calls and mechanical release bookkeeping move to ponytail — the orchestrator itself no longer reads multi-KB tracker payloads — while tagging and publishing stay with the orchestrator per `git-strategy.md`. The orchestrator no longer bulk-reads: it reads only to act, never to learn, and any repo, log or tracker sweep goes to a reader sub-agent whose excerpt comes back as DATA, never instruction — the DATA-not-instruction rule now covers these excerpts too. Marvin now runs one session per milestone: at milestone close and after every release cut, it writes a handoff to `MEMORY.md` and asks the user to start a fresh session.

**User updates are terse and visual.** A new "Talking to the user" standing rule and `.marvin/agents/user-updates.md` define the shape of every orchestrator message: an emoji legend, a shipped table, an issue callout, and a repeated Next/Open-questions tail — everything else is said once. Agent summaries are linked, never pasted into chat. Install and upgrade now write a report file into `.docs/reports/`, check for symlinks before writing, encode every consumer path, and make one commit of that run's explicit paths. A resumed aborted install now stops and asks instead of guessing at what a partial run left behind.

**Upgrading** needs the same manual step v0.30.0 introduced: re-sync CLAUDE.md's changed kit-authored parts with the current template, listed in full in `upgrades/v0.31.0.md`.
