# v0.33.0 — kit rules stay current on every upgrade

**Consumers must act once.** Run `claude plugin update marvin`, restart Claude Code, then run `/marvin:upgrade-agent-os` and confirm the one-time split of your `CLAUDE.md` when it asks (`upgrades/v0.33.0.md`). After that, no upgrade ever needs a hand edit of `CLAUDE.md` again.

Until now the kit's rules were merged into each project's `CLAUDE.md`, and that file is never refreshed — so every always-on rule change needed a manual re-sync, and a plugin update without the upgrade skill left a project silently running old rules. That is how the v0.31.0 user-update formats went unseen in an upgraded project.

**Kit rules live in a kit-owned file.** `.marvin/CLAUDE.marvin.md` holds the kit's core rules; your `CLAUDE.md` keeps your project facts, conventions, attribution line and own rules, and ends with `@.marvin/CLAUDE.marvin.md`, which Claude Code loads at session start. Every upgrade refreshes the kit file like any other guide, backing up a customised copy. Model names come straight from the plugin's model profile; the issue-log path from `.marvin/PROJECT-INFO.md`.

**A one-time, confirmed split.** The first upgrade to this version separates kit lines from yours with a read-only planner, tells you how many lines of each it found and asks you before writing anything, shows near-copies of kit lines for you to keep or drop, replaces labelled kit lines you had edited with the current rule unless unsure (your version kept in the backup and the report either way), and backs up your `CLAUDE.md`. Declining writes nothing but the report. Older notes' "re-sync CLAUDE.md" steps are skipped automatically.

**Your rules win, gates excepted.** A rule in your own `CLAUDE.md` overrides a kit rule, and Marvin names the conflict once — except the safety gates, which a project file cannot switch off: the completion and security validators, every consent question, destructive-operation guards, and the secrets and commit-hygiene rules.

**Stale installs announce themselves.** A new plugin SessionStart hook runs in Marvin projects only: it warns when the project's install is older (run the upgrade skill) or newer (update the plugin) than the plugin, and injects the short user-update rules every session, after compaction too. It never writes and never blocks.
