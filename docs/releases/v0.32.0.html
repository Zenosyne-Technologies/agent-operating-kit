v0.32.0 — Marvin targets a declared model set

Consumers must act. After claude plugin update marvin, first re-sync CLAUDE.md's Model-tier dispatch section — its concrete model names and two changed lines — with the new profile, and only then run /marvin:upgrade-agent-os, which renders the refreshed guides from those names (upgrades/v0.32.0.md).

Marvin was written model-generic: tier names everywhere, concrete models chosen at install. That stopped holding with Opus 5.5, whose max effort now outperforms the frontier tier (Fable 5.1) for far less cost — a rule written for "any frontier model" gets that wrong. From this version on, each Marvin release is built and validated for a declared model set, and model-specific rules live in one place.

The model profile. .marvin/agents/model-profile.md is the single owner of the version's model set and its model-specific rules: orchestrator Opus 5.5 at medium effort (high when a task needs it), heavy worker Opus 5.5, small worker Sonnet 5, micro Haiku 4.5, frontier Fable 5.1 opt-in only. Every other guide keeps tier names and cites it. It is kit-owned: an upgrade replaces a customised copy (keeping a backup), and running other models is unsupported — Marvin shows one callout when the session's model differs, and never blocks.

The max gate recommends max. When a stuck build task reaches the top of the effort ladder, the question now offers max effort on the orchestrator's model first, as the recommended choice, and the frontier tier second, as the costlier alternative. Everything else about the gate is unchanged.

Install reads the profile. The install skill takes its tier-to-model names from the plugin's profile instead of re-checking at install time. A new validate-kit check (model-names, the 13th) fails any template other than the profile that names Opus, Sonnet, Haiku or Fable.

Later versions will add profiles for other model sets.

This note's scope: was derived over v0.31.0..HEAD, non-merge commits only; the container epic AOS-161 is excluded.

Upgrade

Consumer-facing: this version is built and validated for one model set, declared in the new .marvin/agents/model-profile.md: orchestrator Opus 5.5 at medium (high when needed), heavy worker Opus 5.5, small Sonnet 5, micro Haiku 4.5, frontier Fable 5.1 (opt-in only). Other models are unsupported.

  • claude plugin update marvin first (it changes no installed file).
  • Then, BEFORE running the upgrade skill, re-sync CLAUDE.md's Model-tier dispatch section by hand (merged, never refreshed): set its concrete model names to the profile's set (${CLAUDE_PLUGIN_ROOT}/templates/marvin/agents/model-profile.md), and re-sync the two changed lines — the persona paragraph (now cites model-profile.md and the session-model check) and the Escalate line (max first, recommended, frontier as the costlier alternative). Order matters: step 4b renders the refreshed guides from CLAUDE.md's model names (AOS-160), so re-syncing afterwards leaves the old names in them.
  • Then run /marvin:upgrade-agent-os — step 4b adds model-profile.md and refreshes escalation.md, escalation-ladder.md and token-economics.md, plus every guide that renders a model name (planning-research.md, reporting.md, validation-agent.md) once CLAUDE.md's names changed (customised copies backed up first).
  • The max-gate question now offers max (recommended) before frontier; its defaults are unchanged — no answer means max, only the question tool's answer counts.
  • If your session runs a different orchestrator model, Marvin shows one callout that this version is validated for Opus 5.5; it never blocks.
