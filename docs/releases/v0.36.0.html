v0.36.0 — Claude 5.5 routing, safe updates, what's new

Consumers act once: run claude plugin update marvin, follow the update procedure the SessionStart notice prints (upgrades/v0.36.0.md).

Routing for Claude 5.5. Opus 5.5 orchestrates; Sonnet 5.5 and Haiku 5.5 run their personas pinned to high effort. A new micro-tier developer, marvin:developer-micro (Haiku 5.5), builds anything whose brief passes the fully-specified test: a small task, a peripheral piece or a correction with an exact fix list. Work that needs judgement stays with marvin:developer-small, and briefing.md now says how to write a brief that qualifies.

The climb. A stuck build climbs effort within its tier, then tiers up toward the orchestrator's model, never above it by default: micro, small, a new marvin:escalation-small-xhigh rung (Sonnet 5.5 at xhigh), then the Opus rungs. A micro-tier stop on a choice the brief did not make is a mis-tiering, not a failed round.

The update procedure. The SessionStart notice for a newer Marvin now carries the safe update procedure (when to start a new session, when to upgrade); Marvin relays it as given and never starts an upgrade while agents are working on the project.

Context budget. Session length is governed by context size. A plugin hook advises, never blocks: past 400k tokens Marvin is told the work has grown big and suggests a fresh session at the next clean break; past 700k it starts no new task first. A project moves the budgets with session_soft_ktokens and session_hard_ktokens in .marvin/PROJECT-INFO.md. Without the hook, the kit core falls back to a fresh session at milestone close.

CHANGELOG and what's new. CHANGELOG.md is now categorised from v0.22.0 on (Action needed, Added, Changed, Fixed, Removed, Security), and validate-kit.sh refuses an uncategorised bullet. /marvin:whats-new aggregates the sections between your installed version and the latest, Action needed first.

This note's scope: was derived over v0.35.1..HEAD, non-merge commits only; the container epic AOS-180 is excluded.

Upgrade

Consumer-facing: Marvin targets the Claude 5.5 family. Fully-specified small builds and corrections run on a new micro-tier developer (Haiku 5.5, high effort); judgement work stays on Sonnet 5.5; a stuck small-tier build gets one Sonnet xhigh rung before the Opus rungs. All Sonnet and Haiku personas (marvin:developer-small, marvin:documenter, marvin:developer-micro, marvin:ponytail) are now pinned to high effort.

  • Update with the procedure the SessionStart notice prints (it states the order and when to start a new session); then run /marvin:upgrade-agent-os.
  • No file moves — no migration script. Refreshed guides (customised copies backed up first): model-profile.md, briefing.md, escalation.md, escalation-ladder.md, guardrails.md, planning-research.md, token-economics.md, information-guide.md; the kit core .marvin/CLAUDE.marvin.md is refreshed too. No tracker or label change.
  • Session breaks now follow context size (plugin hook, advisory, never blocks): 400k soft / 700k hard tokens. Override with session_soft_ktokens / session_hard_ktokens (integers, thousands, soft < hard) in .marvin/PROJECT-INFO.md frontmatter. The kit core no longer asks for a fresh session at every milestone close; it does only when no plugin hook runs.
  • If your .docs/information/ files use relevance:, the new legal values are developer-micro and escalation-small-xhigh.
  • Start a new session after the upgrade so the new personas, rules and hooks load.
  • Ask /marvin:whats-new for the categorised list of what changed since your version.

Changes

Added

  • A micro-tier developer (marvin:developer-micro, Haiku 5.5 at high effort) builds fully-specified small tasks, pieces and corrections.
  • A small-tier escalation rung (marvin:escalation-small-xhigh, Sonnet 5.5 at xhigh) before a stuck small task reaches the Opus rungs.
  • /marvin:whats-new explains what changed between your version and the latest, Action needed first.

Changed

  • Marvin targets the Claude 5.5 family: Opus 5.5 orchestrates, Sonnet 5.5 and Haiku 5.5 run their personas at high effort.
  • A stuck build climbs effort within its tier, then tiers up toward the orchestrator's model, never above it by default.
  • The update notice now carries the safe update procedure: when to start a new session and when to upgrade.
  • Session length follows context size: past 400k tokens Marvin suggests a fresh session at a clean break; past 700k it starts no new task first. Nothing blocks.

  • After /marvin:upgrade-agent-os, start a new session so the refreshed rules, personas and hooks load.
