v0.42.2 — Install and upgrade end with a placeholder check

Consumers act once: update the plugin. No installed file changes; the next /marvin:upgrade-agent-os ends with the new check.

Why. A haiku-driven install once reported success while three placeholders stayed unresolved ({{TRACKER_GUIDE_URL}} and {{TRACKER_COORDINATES}} in ticket-filing.md, {{PROJECT_KEY}} in tracker-config.md). The install skill relied on the model's diligence. Now a script closes it out.

What changed.

  • scripts/marvin-placeholder-check.sh <root> is read-only. It prints one unresolved: <path>:<line>:{{NAME… line per hit and exits 0 (clean), 1 (hits) or 2 (the check failed, with a one-line reason; never a silent clean).
  • It matches every {{NAME…}} form: {{NAME}}, {{NAME: …}} and {{NAME + …}}.
  • It scans only the kit-written set:
    • .marvin/, excluding runs/, reports/ and backups/;
    • the .docs/ files that mirror the plugin's templates/docs/, derived at run time, including the three audience handbook indexes;
    • the root CLAUDE.md.
  • The dispatch-time placeholders of stats-collection-brief.md ({{SCOPE…}}, {{PERIOD_DAYS}}) are exempt. A test ties that list to the briefs, so a new dispatch-time placeholder fails the suite.
  • Install step 10 and upgrade step 7 run it with an explicit . root before their report and commit. Every hit in a file the run wrote is resolved, and the check re-runs until only reportable lines remain. A hit it cannot resolve, or one in consumer-owned content, goes into the report as a count and is never edited.
  • scripts/test-placeholder-check.sh (98 checks, every guard mutation-tested) runs in CI.

Acceptance.

  • The check was run read-only against the 10 Marvin installs on the maintainer's machine (kit 0.26.1–0.34.0). It flagged exactly one real leftover, {{TRACKER_COORDINATES}} in one project's .marvin/agents/ticket-filing.md, the same failure that motivated it. The other nine were clean, with no false positives.
  • validate-kit and every suite are green.
  • The haiku-driven scratch re-install from the DoD was not run for this release: the maintainer's Claude CLI sign-in had expired. It is recorded on AOS-221 as the remaining acceptance step.

This note's scope: was derived over v0.42.1..HEAD, non-merge commits only.

Upgrade

Consumer-facing: install and upgrade now end with a mechanical check that no {{PLACEHOLDER}} was left unresolved — no installed file changes.

  • Update the plugin. Nothing to run in the project and no file to refresh: the change is in the plugin's install and upgrade skills and a new scripts/marvin-placeholder-check.sh.
  • To check an existing install once, run /marvin:upgrade-agent-os (it now ends with the check) or ask Marvin to run the placeholder check. A reported .marvin/ or .docs/ hit is a placeholder an earlier install left: resolve it from the repo's facts. A hit in consumer-owned content is reported only.
  • No migration script, no new settings.

Changes

Added

  • scripts/marvin-placeholder-check.sh: a read-only check that no install-time {{PLACEHOLDER}} is left in the files the kit writes (.marvin/ minus runs/reports/backups, the seeded .docs/ files, root CLAUDE.md); exit 0 clean, 1 hits, 2 check failed.
  • scripts/test-placeholder-check.sh, mutation-tested and run in CI.

Changed

  • Install (step 10) and upgrade (step 7) end with the placeholder check: hits in files the run wrote are resolved, and what cannot be resolved or sits in consumer-owned content is reported as a count, never edited.

Action needed

  • None: update the plugin; the next /marvin:upgrade-agent-os runs the check.
