v0.39.0 — host tidying and ticket-filing standards

Consumers act once: run claude plugin update marvin, follow the update procedure the SessionStart notice prints (upgrades/v0.39.0.md), then label or remove your existing Docker resources by hand.

Docker tidying. Every Docker resource an agent creates carries four labels: marvin.project, marvin.checkout, marvin.owner and marvin.lifetime. The new .marvin/agents/tidying.md owns the rules: naming, throwaway versus keep, who removes what, and the handoff listing. The plugin's Docker sweep runs at session start and in /marvin:clean-worktrees; it removes throwaway containers, networks, volumes and images whose owner worktree is gone, and keeps a resource when any of seven guards holds (D0 another checkout, D1 not throwaway, D2 main-owned or no owner, D3 an owner name that fails validation, D4 the worktree still exists, D5 a container still running, D6 docker refused the removal), plus D7: an image with several tags, which it never untags. A Docker lint advises on unlabelled resources and on compose stacks without a project name. Resources created before this upgrade carry no labels and are never swept.

Throwaway databases. A database snapshot, copy or instance made for a sandbox, test run or agent worktree runs with binary logging off. The Docker lint advises when a throwaway MySQL or MariaDB container is started with it on, and never touches the project's real databases.

Ticket-filing standards. Label registry v1.5.0 requires size: on every non-epic item at filing, treats a size or severity written only in prose as unlabelled, and fixes the severity spelling (sev4-low). The ticket lint checks tracker writes to the project's own tracker (Jira, Linear, GitHub, Local) before they happen: with ticket_lint: block (the default) a violation is denied, with advise it is a note, with off nothing runs. A gh command it cannot parse with certainty only gets advice. The tracker intake brief gains an audit of open items: it reports by default, and the upgrade asks one yes/no before backfilling the flagged items. AOS-219 was a Jira-only backfill of existing items with no commits, so it is named here, not in scope.

Acceptance. On a scratch install of the local checkout (claude -p --model haiku, 2026-10-15), replayed live against the shipped hooks: the ticket lint denied a Local issue Write that had no size: label and stated its size in prose, citing label-syntax.md; the model retried with size:m and no prose, and with ticket_lint: off the same write passed. The Docker lint advised on an unlabelled docker volume create. The SessionStart Docker sweep removed a finished worktree's throwaway volume and kept, and reported, a main-owned one. The SubagentStart rules carry rule (6). The Local intake ran its audit report-only (audit: flagged 0/backfilled 0) and asked no backfill question. The haiku-driven install left three placeholders unresolved (the tracker guide URL and coordinates in ticket-filing.md, the project key in tracker-config.md), skipped the attribution settings and the style-plugin finder, and committed a stray brief copy; each was finished by hand as the skill specifies.

This note's scope: was derived over v0.38.0..HEAD, non-merge commits only; the container epic AOS-215 is excluded.

Upgrade

Consumer-facing: agents now label and clean up their Docker resources, run throwaway databases without binary logging, and file tracker items with every required label. Rules: .marvin/agents/tidying.md and .marvin/agents/ticket-filing.md.

  • Update with the procedure the SessionStart notice prints. No file moves, so no migration script.
  • The upgrade adds .marvin/agents/tidying.md; refreshes label-syntax.md (v1.5.0), ticket-filing.md, ponytail.md, worktrees.md, guardrails.md, briefing.md and the kit core .marvin/CLAUDE.marvin.md (customised copies are backed up first); and adds ticket_lint: block to .marvin/PROJECT-INFO.md.
  • It re-dispatches the tracker's intake brief: a guide refresh plus a report-only label audit of every open item. It then asks ONE yes/no on backfilling the flagged items; on no, they are only reported.
  • New plugin hooks: the Docker sweep (session start and /marvin:clean-worktrees), the Docker lint (advises on unlabelled resources, compose stacks without a project name, and throwaway MySQL/MariaDB with binary logging on) and the ticket lint (ticket_lint: block | advise | off; project's own tracker only).
  • Label your Docker resources per tidying.md (marvin.project, marvin.checkout, marvin.owner, marvin.lifetime). Resources created before this upgrade carry no labels and are never swept, so remove them by hand.
  • Start a new session after the upgrade so the hooks and rules load.

Changes

Added

  • A Docker sweep (session start and /marvin:clean-worktrees) removes the throwaway containers, networks, volumes and images of finished agent worktrees, keeping anything that is another checkout's, not throwaway, main-owned, still in use, or an image with several tags.
  • Four Docker labels (marvin.project, marvin.checkout, marvin.owner, marvin.lifetime) that every agent-created resource carries; the new .marvin/agents/tidying.md owns them.
  • A Docker lint advises on unlabelled resources, compose stacks without a project name, and throwaway MySQL/MariaDB containers with binary logging on; throwaway databases now run with binary logging off.
  • A ticket lint checks tracker writes to the project's own tracker for the required labels and registry values (ticket_lint: block | advise | off); a gh command it cannot parse with certainty only gets advice.
  • The intake brief's label audit: it reports non-conforming open items by default and backfills only after you say yes.

Changed

  • Label registry v1.5.0: size: on every non-epic item at filing, labels never prose, severity spelled exactly (sev4-low).
  • When the upgrade's label audit flags items on your tracker, it asks ONE yes/no on backfilling them.

Fixed

  • Tracker items filed with a size or severity only in prose, or with bare sev4, are now flagged instead of passing as labelled — denied under ticket_lint: block when the write can be read with certainty, advised otherwise.

Action needed

  • Label your Docker resources per tidying.md; resources created before this upgrade carry no labels and are never swept, so remove them by hand.
  • After /marvin:upgrade-agent-os, start a new session so the new hooks and rules load.
