v0.43.0 — Fable 5.2 profile and the model_profile setting

Consumers act once: run /marvin:upgrade-agent-os. It asks once for model_profile: opus | fable; no answer writes opus. See upgrades/v0.43.0.md.

Why. Fable 5.2 can run the main session, but it costs about twice the orchestrator per-token price and needs 30-day data retention, so it must be a choice. The kit also hard-wired the orchestrator to the heavy tier's model; the two now move independently.

What changed.

  • model-profile.md carries two declared sets, opus (default) and fable. In opus the frontier tier moves to Fable 5.2. Under fable the orchestrator runs Fable 5.2, heavy/small/micro are unchanged, there is no frontier tier, and the max gate offers max only.
  • model_profile is a PROJECT-INFO key: install and upgrade ask once (no answer or unattended: opus), project-info validates it, /marvin:info reports it, and switching re-renders the kit core, ladder, escalation.md, validation-agent.md and model-profile.md.
  • New placeholders {{ORCHESTRATOR_MODEL}}, {{MODEL_PROFILE}}, {{FRONTIER_SWAP_OPTION}}; the ceiling is the heavy tier's model, rule 1 is kept and re-dated (re-measure pending AOS-272).
  • The Codex table moves to .marvin/agents/model-profile-codex.md; the legacy section is still read until moved.
  • Factory: kit-core budget 55 → 100 (AOS-266); validate-kit gains profile-parity, a per-profile profile-window and model-names over both profile files (25 checks), plus test-codex fixtures; repo rule 10 (AOS-281) and rule 11 (AOS-296); the install skill's telemetry advice named the wrong marketplace, now fixed with a marketplace check (AOS-297).

Acceptance. Documentation, checked (repo rule 10):

  • README: inventory, gate count (25) and list, suite count (18), skills table, feature section and portability bullet.
  • docs/index.html: both profiles in the escalation staircase, tier legend Fable 5.2, model_profile mentioned; no screenshots (no mod change).
  • CLAUDE.md / AGENTS.md: budget, model-names clause, declared profiles.
  • PROJECT-INFO template, install, upgrade and project-info skills, /marvin:info.
  • upgrades/v0.43.0.md and the CHANGELOG.md section.

Behaviour (AOS-271), on the Local tracker only (the render is tracker-independent; no Jira scratch install):

  • Scratch installs for opus and fable: PASS. ORCHESTRATOR_MODEL renders Opus 5.5 / Fable 5.2; the fable max gate is max-only; the placeholder check exits 0; model-profile.md names the profile.
  • v0.42.2 → v0.43.0 upgrade with no key and no answer: asked once, opus written, and .marvin/ identical to a fresh opus render except the consumer-owned PROJECT-INFO body bullet.
  • Pending: the Fable-orchestrated real size:s run (architect). AOS-271 stays in Testing, and the fable set's validation line stays "pending AOS-271".

This note's scope: was derived over v0.42.2..HEAD (git log --no-merges), AOS- prefixes deduplicated, container epic AOS-265 dropped.

Upgrade

Consumer-facing: a new model_profile: opus | fable setting picks the model set; the frontier tier is now Fable 5.2.

  • Run /marvin:upgrade-agent-os. It asks ONCE for model_profile when the key is missing; no answer or an unattended run writes opus (today's set, no spend change). fable runs the main session on Fable 5.2 (about 2x orchestrator per-token cost; needs 30-day data retention, not ZDR); heavy, small and micro tiers are unchanged and its max gate offers max only.
  • An invalid held value (Fable, sonnet, empty) STOPs the upgrade before any write: correct the key and re-run.
  • To switch later, edit model_profile and run /marvin:upgrade-agent-os (re-renders the kit core, ladder, escalation.md, validation-agent.md, model-profile.md).
  • Step 4a adds .marvin/agents/model-profile-codex.md. Step 4b refreshes model-profile.md without its Codex section, and refreshes (with backups) CLAUDE.marvin.md, escalation-ladder.md, escalation.md, validation-agent.md, token-economics.md, fleet.md, codex.md.
  • A customised Codex table lands in .marvin/backups/v0.43.0/: move it into model-profile-codex.md by hand (until then marvin-codex.sh still reads the legacy section).
  • The model_profile bullet in the PROJECT-INFO.md body is not added (consumer-owned file); its meaning is in model-profile.md.
  • Token-telemetry users: run /token-telemetry:pricing-update for claude-fable-5-2 pricing.
  • No migration script.

  • .marvin/agents/model-profile-codex.md: the Codex table moves out of model-profile.md (the legacy section is still read until moved).
