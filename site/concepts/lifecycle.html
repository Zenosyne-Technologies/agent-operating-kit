Concepts

The task lifecycle

Every tracker task runs one loop. Marvin plans, briefs and sequences. Specialised personas build, check and document, each pinned to a model tier. A task needs a verifiable definition of done (DoD) before it can enter build: builders work to it, and validators try to falsify it.

The loop

Each arrow is a gate: the next stage starts only after this one passed. Select any persona in the diagram to see its model, its job and its limits in the panel at the foot of the page.

Personas are buttons: click one, or Tab to it and press Enter. On a narrow screen, scroll the diagram sideways.

Stage by stage

  1. Plan and brief. Marvin writes the DoD on the tracker issue, gives the task its size: label and writes the brief the builder works from (briefing.md).
  2. Build. The size label and how complete the brief is pick the builder. Sizing shows the four lanes.
  3. Completion gate. A fresh validator, never the builder, tries to falsify "done" against the DoD (validation-agent.md).
  4. Security gate. Runs only after completion passes, and reviews the changes for security regressions (security.md).
  5. Visual review. UI tasks only, after both gates pass. It is advisory: it never gates or bounces the task (visual-validation.md).
  6. Document gate. Only after both validators pass. The tracker issue cannot close before the docs and handbooks land (documentation-agent.md).
  7. Close-out. Marvin runs the close-out check, a micro persona makes the tracker call, and the issue closes with its commit refs (ticket-filing.md).

A failed gate sends the task back to its build tier with the findings, and counts as one failed round. The fixed build re-enters at the completion gate, never at document or close. What Marvin does after a failed round is on Escalation.

Model profiles

Each tier runs on the model the project's model profile picks. The chips and the persona panel show the default profile. The table lists every profile this kit version declares. A profile can put the orchestrator a tier above the heavy worker, but no sub-agent runs above the heavy tier's model unless you ask for it.
