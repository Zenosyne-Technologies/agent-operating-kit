# v0.23.0 — agent guardrails, a code-documentation convention, and a self-scoped installed LICENSE

Nothing moves or is renamed, so there is no `migrate-v0.23.0.sh` — the steps below are the whole upgrade. As on every release, the kit-owned guides in `.marvin/agents/` are re-rendered from the current templates and anything replaced is backed up to `.marvin/backups/v0.23.0/`; reconcile customisations from there.

1. **Guardrails arrive as a new guide.** The refresh above adds `.marvin/agents/guardrails.md` (the "DO NOT" framework — four dispositions, the escalation chain, a generic baseline plus per-persona rows) and updates `briefing.md` (a guardrails ingredient with a reserved `GUARDRAILS:` final-message line) and `information-*.md` (de-numbered cross-references). Add ONE cascade row to `CLAUDE.md`, verbatim from the current `CLAUDE.core.md`: `- Bound by a DO NOT — about to do something destructive, out-of-scope or irreversible → \`.marvin/agents/guardrails.md\` (the four dispositions, the escalation chain, the generic baseline + your persona's rows)`. Place it where `CLAUDE.core.md` has it — after the reporting row, before the handbooks row.
2. **Builders now write docblocks.** `.marvin/agents/documentation-agent.md` item 2 gains a code-documentation convention: every new/modified public class or method carries a language-standard docblock (PHPDoc, TSDoc, Javadoc, PEP 257, …), reconciled with the non-obvious-inline-comment rule. It arrives with the refresh; nothing else to do.
3. **`.marvin/LICENSE` is installed.** A self-scoped copy of the kit's license notice (PolyForm Noncommercial 1.0.0, holder ZENOSYNE Kft.) is seeded create-if-missing, then kept current by the kit-owned refresh. If you already have one, a superseded notice is backed up before replacement.
4. **Build personas update out-of-band.** The `marvin:*` personas ship WITH the plugin, not as files in your repo — update them with `claude plugin update marvin`, not by editing anything under `.marvin/`.
