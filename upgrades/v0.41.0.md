# v0.41.0 — Fleet mode (nested orchestrators for parallel epics)

Consumer-facing: **a master orchestrator can now run up to three child orchestrators, one per epic, with one board for the architect — opt-in with `/marvin:fleet`, off until you start it.** Rules: `.marvin/agents/fleet.md` (master) and `.marvin/agents/fleet-child.md` (child).

- Update with the procedure the SessionStart notice prints. No file moves, so no migration script.
- The upgrade adds `.marvin/agents/fleet.md` and `.marvin/agents/fleet-child.md`, and refreshes `git-strategy.md`, `session-budget.md`, `worktrees.md`, `escalation.md`, `escalation-ladder.md`, `guardrails.md`, `codex.md` and the kit core `.marvin/CLAUDE.marvin.md` (one new cascade line; customised copies are backed up first).
- Nothing to add to `.marvin/PROJECT-INFO.md`: the three fleet keys (`fleet_max_children`, `fleet_max_compactions`, `fleet_restart_max_pct`) are optional, defaults 3 / 3 / 33; `/marvin:project-info` validates them only when present.
- Fleet mode needs a shared tracker (Linear, Jira or GitHub) and local child sessions (the Claude Code desktop app); on other hosts it runs as a manual fleet with resume prompts. The Local tracker is refused.
- The context hook now reads a per-worktree role marker (one `git rev-parse` per call); a session that is not in a fleet sees exactly the same messages as before.
- **Start a new session after the upgrade** so the rules load.
