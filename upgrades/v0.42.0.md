# v0.42.0 — Session clean-up fix (session worktrees and run state survive clean-up)

Consumer-facing: **the automatic worktree sweep now removes only worktrees Marvin marked as its own, and run state (ledger, briefs, run reports) lives in the project's `.marvin/runs/<session>/<KEY>/`, carried there by hooks from any worktree.** Rules: `.marvin/agents/worktrees.md` and `.marvin/agents/briefing.md` item 11.

- **Before updating the plugin**, decide enforcement in `.marvin/PROJECT-INFO.md` frontmatter. An absent key never enforces: `ticket_lint` → advise, `worktree_sweep` → check (report only), `docker_lint` → advise. The upgrade writes `ticket_lint: block`, `worktree_sweep: on` and `docker_lint: advise` only where a key is missing, directly after `ticket_lint`.
- Update with the procedure the SessionStart notice prints. Then run `/marvin:upgrade-agent-os` in ONE session. It refreshes the cascade (new `session-recovery.md`; `briefing.md`, `worktrees.md`, `tidying.md`, `git-strategy.md`, `ticket-filing.md`, `escalation-ladder.md`, `validation-agent.md`, `session-budget.md`, the kit core). Its new step 6b moves existing run state into the per-session layout with `marvin-runs-migrate.sh`. It asks which sessions are still open mid-task and defers those.
- **Restart every other open session**, because sessions started earlier run the old, unscoped sweep until restarted. `/clear` or restart the upgrading session before its next task.
- **Once the deferred sessions have finished or been cleared**, run `/marvin:upgrade-agent-os` again. It moves the run state it deferred.
- Agent worktrees made before this release are never swept by the kit; remove them by hand or leave them. Desktop session worktrees are left to the app's own clean-up.
