# v0.33.0 — kit rules stay current on every upgrade; stale installs announce themselves

Consumer-facing: **no more hand re-syncing CLAUDE.md.** The kit's rules move out of your `CLAUDE.md` into a kit-owned `.marvin/CLAUDE.marvin.md` that `CLAUDE.md` imports; every future upgrade refreshes it for you.

- `claude plugin update marvin`, then **restart Claude Code** (loads the new SessionStart hook), then run `/marvin:upgrade-agent-os`.
- **Confirm the one-time split when asked** — before it writes anything, the upgrade shows which `CLAUDE.md` lines are kit rules (moved into `.marvin/CLAUDE.marvin.md`), which are yours (kept), and any near-copy of a kit line without its label for you to keep or drop; a labelled kit line you had edited is replaced by the current rule, your version kept in the backup and listed in the report. It backs up your `CLAUDE.md` under `.marvin/backups/v0.33.0/`, ends it with the line `@.marvin/CLAUDE.marvin.md`, and keeps your attribution line. Declining or not answering stops the upgrade having written only its report.
- **Skip every older note's "re-sync CLAUDE.md" step** — including v0.32.0's hand-edit of model names; the upgrade skill does this for you and edits `CLAUDE.md` only in the split (and to re-add the import line if you removed it).
- `.marvin/PROJECT-INFO.md` gains `issue_log_path`; model names now always come from the plugin's model profile.
- Your own `CLAUDE.md` rules override kit rules, except the kit's safety gates (validators, consent questions, destructive-operation guards, secrets and commit-hygiene rules).
- New SessionStart hook: in a Marvin project it warns when the install and plugin versions differ, and injects the short update-format rules each session. Disable with `/plugin disable marvin` or `"disableAllHooks": true`.
- If `.marvin/` is gitignored, the upgrade flags it — the import would load nothing in other clones.
- A fresh install in an AGENTS.md-only repo writes a `CLAUDE.md` that imports `@AGENTS.md`; the kit never writes AGENTS.md.

This note's scope was derived over `v0.32.0..HEAD`, non-merge commits only; the container epic AOS-164 is excluded.
