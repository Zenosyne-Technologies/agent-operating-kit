# v0.22.0 — gitflow replaces the milestone branch; `.docs/release-notes/` joins the estate

Nothing moves or is renamed, so there is no `migrate-v0.22.0.sh` — the steps below are the whole upgrade. As on every release, the kit-owned guides in `.marvin/agents/` are re-rendered from the current templates and anything replaced is backed up to `.marvin/backups/v0.22.0/`; reconcile customisations from there.

1. **Your branch convention changes.** `milestone/<KEY>-<slug>` is gone. Work runs on gitflow: `main` holds released state only, `develop` integrates, ONE `feature/<KEY>-<slug>` per work item, `release/<version>` and `hotfix/<version>` merged BOTH ways. A new guide, `.marvin/agents/git-strategy.md`, arrives with the refresh above and owns that model plus tagging authority (annotated tags, orchestrator only) and semver classification. Merge three things into `CLAUDE.md`, taking each verbatim from the current `CLAUDE.core.md`: the cascade row `- Branching, versioning, tagging, or cutting a release — any git decision beyond a commit → \`.marvin/agents/git-strategy.md\``; the **Git, branches, releases** standing rule, REPLACING the old **Milestone feature branching** one; and the task-lifecycle paragraph's last sentence, which now ends `…, and the closer merged and deleted its branch per \`.marvin/agents/git-strategy.md\`` — a task that closes without merging is work nobody will find. Finish and merge any in-flight `milestone/*` branch as it is; cut everything new from `develop`.
2. Seed `.docs/release-notes/index.md`, and MERGE its row into the sub-folder table of the `.docs/index.md` you already have — every existing row and paragraph stays, that one row gets added. A seeded folder no row points at is unreachable from the crawl's entry point, which means it does not exist.
3. **Two prose edits the row-merge above does not cover** — apply them by hand in your `.docs/index.md`, copying verbatim from `templates/docs/index.md`: append `What one RELEASED version changed → \`release-notes/\`.` to the "Where a new document goes" paragraph, and change the root-level-documents paragraph's folder count from "six" to "seven" (`the seven folders above take everything…`). Without these nothing routes a writer to `release-notes/` and the count still lies.
4. **Release notes carry a mandatory `scope:` header.** `release-note` is a new `type:` in `document-standard.md`, and for it `scope:` is required: that version's work-carrying issue keys (containers expanded), derived at the cut per `git-strategy.md` step 4 (previous tag, or the previous release's commit when you have no tags yet), never recalled, and the note records which range it used. Release-scoped reporting and cost resolve against that field and nothing else.
5. **Stats snapshot schema 2 → 3.** `tokens: null` now means ONLY "the telemetry DB is absent". Otherwise `tokens` is an object whose `state` is `ok` / `scope-unresolved` / `no-rows`, always carrying `scope_issue_keys` and `control_events`, and carrying the figures only when `state: ok`. Renders print no currency figure at all for the other two states — not even zero. Snapshots already written to `.docs/reports/` stay at schema 2: they are a record, leave them.
6. Your `.marvin/agents/stats-collection-brief.md` accepts a third SCOPE, `release:v<version>`, which reads the note's `scope:` header instead of querying the tracker.
7. **Jira installs only**: a `release:v<version>` label dimension joins `milestone:<slug>` (label registry v1.3.0) — on every issue that shipped, tasks included, while `milestone:` stays on epics; the same `convert-milestones-brief.md` converts both axes to fixVersions. GitHub, Linear and Local map releases natively and must NOT use the label. Re-running the intake brief seeds it.
8. Restamp `.marvin/PROJECT-INFO.md`: `kit_version: 0.22.0` and `label_syntax_version: 1.3.0`.
