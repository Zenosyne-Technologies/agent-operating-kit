# v0.32.0 — Marvin targets a declared model set (Opus 5.5)

Consumer-facing: **this version is built and validated for one model set**, declared in the new `.marvin/agents/model-profile.md`: orchestrator Opus 5.5 at medium (high when needed), heavy worker Opus 5.5, small Sonnet 5, micro Haiku 4.5, frontier Fable 5.1 (opt-in only). Other models are unsupported.

- `claude plugin update marvin`, then run `/marvin:upgrade-agent-os` — its step 4b adds `model-profile.md` and refreshes `escalation.md`, `escalation-ladder.md` and `token-economics.md` (customised copies backed up first).
- **Re-sync CLAUDE.md's *Model-tier dispatch* section** (merged, never refreshed) with the current template — two lines changed: the tier bullets now cite `model-profile.md`, and the Escalate line puts **max first, recommended**, with the frontier tier as the costlier alternative.
- **Re-sync the concrete model names** in that section's dispatch table to the profile's set by hand — the upgrade skill still reads them back from your CLAUDE.md (AOS-160), so an older install keeps its old names until you do.
- The max-gate question now offers max (recommended) before frontier; its defaults are unchanged — no answer means max, only the question tool's answer counts.
- If your session runs a different orchestrator model, Marvin shows one callout that this version is validated for Opus 5.5; it never blocks.

This note's scope was derived over `v0.31.0..HEAD`, non-merge commits only; the container epic AOS-161 is excluded.
