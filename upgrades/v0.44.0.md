# Upgrade to v0.44.0

Consumer-facing: **a new `security_rules: kit | codeguard` setting offers Project CodeGuard's security rules on top of the kit checklist.** Rules: `.marvin/agents/codeguard.md`.

- Update the plugin, then run `/marvin:upgrade-agent-os`. It asks the CodeGuard question ONCE when `security_rules` is missing and inserts the key in `.marvin/PROJECT-INFO.md` right after `codex_evidence`; no answer or an unattended run writes `kit` (today's behaviour, nothing installed).
- A yes runs `claude plugin marketplace add 'cosai-oasis/project-codeguard#v1.5.0' --scope project` (only when `.claude/settings.json` does not already declare `project-codeguard`) and `claude plugin install codeguard-security@project-codeguard -s project`, writes `security_rules: codeguard`, and the plugin is active from the next session. A failed install writes `kit` and the upgrade continues.
- The install changes `.claude/settings.json` (`extraKnownMarketplaces`, `enabledPlugins`): commit it, so teammates are offered the plugin when they trust the folder.
- A teammate without the plugin on a `codeguard` project gets one notice per session and runs the kit checklist alone; the absence never fails or blocks a task.
- Later upgrades only check: on a `codeguard` project a disabled, removed or drifted plugin is an issue callout, and the key is never changed. To switch later, edit `security_rules`; for `codeguard`, install the plugin with the fix command in `codeguard.md`.
- New cascade file `.marvin/agents/codeguard.md`; refreshed (with backups) `security.md`, `briefing.md`, `validation-agent.md`, `codex.md`, `codex/security.md` and the kit core `CLAUDE.marvin.md`.
- No migration script.
