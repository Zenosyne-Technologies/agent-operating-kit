# Validate the kit

1. **Static gate**: run `bash scripts/validate-kit.sh` from the repo root. Any FAIL stops here — fix before scenarios.
2. **Scenarios** — each in a throwaway git-initialized scratch repo (temp dir; delete afterward). Act as the installing/upgrading agent yourself, following the skills literally with `${CLAUDE_PLUGIN_ROOT}` = this repo root. Tracker steps run DRY (the Local tracker's brief is repo-local and always dispatches for real): fill the briefs and show them, do not dispatch — unless the user names a sandbox tracker project.
   - (a) **Fresh install**: seed a minimal repo (README + one manifest), run `skills/install-agent-os/SKILL.md` selecting the **Local** tracker (no external tool needed), attribution default. Verify: `.marvin/agents/` complete for the selection, `.marvin/agents/stats-collection-brief.md` present, `.docs/project-management/` scaffolded (INDEX.md, `issues/`, `milestones/`, `guide.md`) when the local intake brief is dispatched, three handbook index.md files present (developer/user/admin), `.marvin/MEMORY.md` present, CLAUDE.md placeholders all resolved, PROJECT-INFO frontmatter parses with every template key and real values (14 frontmatter keys incl. `telemetry`), no `{{` and no `${CLAUDE_PLUGIN_ROOT}` in installed files.
   - (b) **Legacy upgrade**: fabricate a pre-0.7.0 shape (`docs/agents/` with old files, `found-by:*` in ticket-filing, no PROJECT-INFO), run `skills/upgrade-agent-os/SKILL.md`. Verify: files moved to `.marvin/agents/`, `.marvin/agents/stats-collection-brief.md` present, three handbook index.md files present (developer/user/admin), `.marvin/MEMORY.md` present, references rewritten, frontmatter created and stamped (14 frontmatter keys incl. `telemetry`), relabel sweep OFFERED not executed.
   - (c) **Current-layout upgrade** — the shape this release actually migrates. Fabricate a **v0.20.0** install and commit it: `.docs/agents/` (full cascade incl. `tracker-config.md` + `stats-collection-brief.md`), `.docs/PROJECT-INFO.md` stamped `kit_version: 0.20.0`, `.docs/marvin/MEMORY.md`, `.docs/handbooks/{developer,user,admin}/INDEX.md`, plus `.docs/project-management/INDEX.md` and `.docs/reports/` as decoys, and a CLAUDE.md citing the old paths. Run `skills/upgrade-agent-os/SKILL.md`. Verify **with `git ls-files`, never `ls`**: `.marvin/agents/`, `.marvin/PROJECT-INFO.md`, `.marvin/MEMORY.md` tracked; `.docs/handbooks/*/index.md` tracked **lowercase** and no `INDEX.md` remains under `.docs/handbooks/` (`ls` lies on case-insensitive filesystems — this is the check that catches a skipped case-only rename); `.docs/project-management/INDEX.md` and `.docs/reports/` untouched; no `.docs/agents|.docs/PROJECT-INFO|.docs/marvin` reference left in CLAUDE.md; history preserved (`git log --follow` on a moved file). Then three edge fixtures, each its own scratch repo: (i) **interrupted rename** — commit a `.docs/handbooks/developer/__index.tmp` with no `INDEX.md` and no `index.md`, run the migration, assert it RESUMES to `index.md` and no `__index.tmp` remains tracked; (ii) **non-empty `.docs/marvin/`** — add a consumer-owned file beside `MEMORY.md`, assert the run completes (handbook renames still land) and the consumer file survives; (iii) **both directories tracked** — commit `.docs/agents/` and `.marvin/agents/` together, assert the migration REFUSES that move, reports the collision, and `git ls-files` shows no `.marvin/agents/agents/`.
   - (d) **No-op**: re-run the upgrade flow on (a)'s result, and again on (c)'s result. Verify both: clean `already at <version>` report, 0 moves performed, `git status --short` empty, HEAD unchanged.
3. **Report**: static-gate result, per-scenario PASS/FAIL with the failed assertion and file diff when failing, and any judgment calls the skills forced (template wording gaps) — those are polish candidates, not blockers.
