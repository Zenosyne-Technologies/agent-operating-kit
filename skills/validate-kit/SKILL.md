# Validate the kit

1. **Static gate**: run `bash scripts/validate-kit.sh`, `bash scripts/test-migrations.sh` **and** `bash scripts/mutate-migrations.sh` from the repo root. Any FAIL stops here — fix before scenarios. The migration suite owns the release-migration mechanics as executable fixtures (one per known defect, plus `--check` purity, re-run no-op and `git revert` consistency); the scenarios below check the *skills* wrapped around them, not the mechanics.
2. **Scenarios** — each in a throwaway git-initialized scratch repo (temp dir; delete afterward). Act as the installing/upgrading agent yourself, following the skills literally with `${CLAUDE_PLUGIN_ROOT}` = this repo root. Tracker steps run DRY (the Local tracker's brief is repo-local and always dispatches for real): fill the briefs and show them, do not dispatch — unless the user names a sandbox tracker project.
   - (a) **Fresh install**: seed a minimal repo (README + one manifest), run `skills/install-agent-os/SKILL.md` selecting the **Local** tracker (no external tool needed), attribution default. Verify: `.marvin/agents/` complete for the selection, `.marvin/agents/stats-collection-brief.md` present, `.docs/project-management/` scaffolded (INDEX.md, `issues/`, `milestones/`, `guide.md`) when the local intake brief is dispatched, the `.docs/` estate seeded (`index.md`, the five folder seeds, `handbooks/index.md` and the three audience index.md files) with every sub-folder row resolving to a file that exists, `.marvin/MEMORY.md` present, CLAUDE.md placeholders all resolved, PROJECT-INFO frontmatter parses with every template key and real values (14 frontmatter keys incl. `telemetry`), no `{{` and no `${CLAUDE_PLUGIN_ROOT}` in installed files.
   - (b) **Legacy upgrade**: fabricate a pre-0.7.0 shape (`docs/agents/` with old files, `found-by:*` in ticket-filing, no PROJECT-INFO), run `skills/upgrade-agent-os/SKILL.md`. Verify: files moved to `.marvin/agents/`, `.marvin/agents/stats-collection-brief.md` present, the `.docs/` estate seeded (root index, five folder seeds, `handbooks/index.md` and the three audience index.md files), `.marvin/MEMORY.md` present, references rewritten, frontmatter created and stamped (14 frontmatter keys incl. `telemetry`), relabel sweep OFFERED not executed.
   - (c) **Current-layout upgrade** — the shape this release actually migrates. Fabricate a **v0.20.0** install and commit it: `.docs/agents/` (full cascade incl. `tracker-config.md` + `stats-collection-brief.md`), `.docs/PROJECT-INFO.md` stamped `kit_version: 0.20.0`, `.docs/marvin/MEMORY.md`, `.docs/handbooks/{developer,user,admin}/INDEX.md`, plus `.docs/project-management/INDEX.md` and `.docs/reports/` as decoys, and a CLAUDE.md citing the old paths. **First, on that fixture, exercise the pre-v0.21.0 fallback in the four other readers** — `commands/info.md` must report **installed + upgradable** and point at `upgrade-agent-os`, never `install-agent-os`; `skills/project-info/SKILL.md` must validate `.docs/PROJECT-INFO.md` IN PLACE and create no second file (a `.marvin/PROJECT-INFO.md` appearing here is the destination collision that stalls the migration at exit 3 and then makes the upgrade a silent no-op); `report` and `plan-docs` must find their facts rather than declare the project uninstalled. Then also restamp a copy's PROJECT-INFO to the current version with the cascade left in `.docs/agents/` and confirm the step-1 **tie-break** still migrates it (layout beats stamp). Run `skills/upgrade-agent-os/SKILL.md`. Verify **with `git ls-files`, never `ls`**: `.marvin/agents/`, `.marvin/PROJECT-INFO.md`, `.marvin/MEMORY.md` tracked; `.docs/handbooks/*/index.md` tracked **lowercase** and no `INDEX.md` remains under `.docs/handbooks/` (`ls` lies on case-insensitive filesystems — this is the check that catches a skipped case-only rename); `.docs/project-management/INDEX.md` and `.docs/reports/` untouched; no `.docs/agents|.docs/PROJECT-INFO|.docs/marvin` reference left in CLAUDE.md; history preserved (`git log --follow` on a moved file). Assert the skill **ran `scripts/migrate-v0.21.0.sh`** for the moves rather than moving files itself, that its `declined:`/`collision:` lines reached the step-7 report in full, and that renames + reference edits landed in ONE commit (`git show --name-only HEAD` holds both; `git revert HEAD` leaves locations and references consistent). Then judge the reference edits the skill made *itself* — that is now the agent's half of the step, and the part a script cannot check: seed the fixture CLAUDE.md with a third-party URL containing `docs/agents/`, an archived `.docs/agents/<file>.md.bak` sibling that does not move, and a changelog line describing the old layout on purpose; all three must survive untouched while the live kit references are updated. The mechanical edge cases (interrupted rename, non-empty `.docs/marvin/`, occupied destination tracked or merely on disk, dirty tree, unsafe repository state, consumer file in `.docs/agents/`) are fixtures in `scripts/test-migrations.sh` — step 1 already ran them; do not rebuild them by hand here.
   - (d) **No-op**: re-run the upgrade flow on (a)'s result, and again on (c)'s result. Verify both: clean `already at <version>` report, 0 moves performed, `git status --short` empty, HEAD unchanged.
   - (e) **Symlink refusal, deletes included**: on a copy of (c)'s post-migration result, replace `.claude/agents/` with a symlink to a directory OUTSIDE the repo holding the seven kit persona copies, and run step 4. It must refuse the WHOLE step naming the path, with every outside-repo file still present — the persona removal is step 4's only deletion, it leaves no backup by construction, and `git status --short` would stay empty while the files were gone. Repeat with `CLAUDE.md` symlinked to `AGENTS.md`: same refusal, and it is documented as clearable, not as a bug. Then close the crawl on (a)'s and (c)'s results: walk from `.docs/index.md` and confirm every `.md` outside `project-management/`/`reports/` is reachable and no link resolves to `.docs/.docs/`.
3. **Report**: static-gate result, per-scenario PASS/FAIL with the failed assertion and file diff when failing, and any judgment calls the skills forced (template wording gaps) — those are polish candidates, not blockers.
