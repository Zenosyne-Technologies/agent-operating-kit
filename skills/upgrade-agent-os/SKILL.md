# Upgrade a Marvin (Agent Operating Kit) install

Current templates: `${CLAUDE_PLUGIN_ROOT}/templates/`. Never overwrite project-specific content — same merge discipline as install.

## Steps

1. **Detect installed state**: read `kit_version` from `.marvin/PROJECT-INFO.md` frontmatter. No stamp? Read `.docs/PROJECT-INFO.md` (pre-v0.21.0 location) before concluding none exists. Fingerprint once: cascade at `docs/agents/` vs `.docs/agents/` vs `.marvin/agents/`; `found-by:` present in taxonomy files (pre-registry); missing `label-syntax.md` / `tracker-config.md` / `planning-research.md` / `PROJECT-INFO.md`; list-style PROJECT-INFO without frontmatter. Report what was detected before changing anything.
2. **Diff by upgrade files**: read `${CLAUDE_PLUGIN_ROOT}/upgrades/` and apply, in semver order, every file AFTER the installed version up to and including the current one — each lists the consumer-visible steps; files stating "No consumer-visible changes" are skipped. Fall back to diffing against `${CLAUDE_PLUGIN_ROOT}/templates/` only where a step is ambiguous or the install predates version stamps (step 1 heuristics). Also track the label-registry delta (installed `label_syntax_version` → current registry H1).
3. **v0.20.0 → v0.21.0 layout migration** (no confirmation — git-revertible; **idempotent**: check each destination first and skip the move when it already exists, so a second run is a no-op that changes nothing). Marvin's machinery leaves `.docs/` for `.marvin/`: `git mv .docs/agents .marvin/agents`, `git mv .docs/PROJECT-INFO.md .marvin/PROJECT-INFO.md`, `git mv .docs/marvin/MEMORY.md .marvin/MEMORY.md` (then remove the emptied `.docs/marvin/`), and for each audience `git mv .docs/handbooks/<audience>/INDEX.md .docs/handbooks/<audience>/index.md` (case-only rename: go via a temp name on case-insensitive filesystems). `.docs/project-management/`, `.docs/reports/` and the handbook pages themselves STAY — they are project record, not machinery. Then rewrite every stale `.docs/agents/`, `.docs/PROJECT-INFO.md`, `.docs/marvin/` and handbook-`INDEX.md` reference in the consumer's own `CLAUDE.md` (and in the migrated files) to the new paths. A pre-`.docs/` install migrates `docs/agents/` → `.marvin/agents/` in one hop. Autocommit.
4. **Migrate remaining repo files** (no confirmation — git-revertible): add missing cascade files INCLUDING the selected tracker's `tracker-config.md` and `stats-collection-brief.md` (from `${CLAUDE_PLUGIN_ROOT}/templates/pm/<tracker>/`, installed to `.marvin/agents/`), and the three `.docs/handbooks/<audience>/index.md` skeletons where missing, with placeholders resolved, and `.marvin/MEMORY.md` where missing; remove kit-installed persona copies from `.claude/agents/` where present (the seven v0.18.0 files — developer, developer-small, validator-completion, validator-security, researcher, documenter, ponytail — now ship WITH the plugin as `marvin:*` agents; only delete files whose content matches the kit's, never a project's own agent); merge CLAUDE.md rule updates without touching project rules; convert a legacy PROJECT-INFO to frontmatter form per the `project-info` skill. Autocommit (attribution per project settings).
5. **Sync tracker structure**: re-dispatch the installed tool's intake brief (idempotent — linear, jira, github, local; sources under `${CLAUDE_PLUGIN_ROOT}/templates/pm/<tracker>/`) as a sub-agent to seed new labels and refresh the guide. Skip when `pm_tool: none` (legacy); `local` dispatches its brief like any other tool. A `none` install may adopt the Local tracker — offer it, and on yes set `pm_tool: local` + install the local tracker files and dispatch its brief (project-key flow per `${CLAUDE_PLUGIN_ROOT}/templates/pm/INSTALL.md`).
6. **Gated data migration**: if the registry delta includes supersessions (mappings in the registry changelog, e.g. `found-by:agent-qa → origin:agent-qa`, `found-by:owner → origin:architect-request`), query the tracker for the affected-issue count and ask ONE yes/no. Yes → dispatch a ponytail (micro-tier) relabel sweep with the mapping as prepared payload. No → report the pending sweep and mapping. Never sweep unasked.
7. **Restamp + report**: update `kit_version` (from `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`) and `label_syntax_version` in the frontmatter; commit. Report: from→to versions, files migrated, labels seeded (from the brief's machine message), sweep executed/pending/none, telemetry opt-in offered (when the token-telemetry plugin is present but `.claude/telemetry` is absent; when the plugin itself is absent — `claude plugin list` — advise installing it: `claude plugin install token-telemetry@emprove`, restart for hooks, with one line on the cost-aware features it adds; the restart rule ALSO applies when the upgrade enables telemetry — capture starts next session, say so), and — if Jira and the connector now supports release creation — that the `convert-milestones` brief is ready to dispatch.

## Rules

- Steps 1–5 and 7 run without confirmation; step 6 is the ONLY interactive gate (shared tracker state is not git-revertible).
- Re-running on a current install must be a clean no-op (report `already at <version>`).
- Installed files stay self-contained: never write `${CLAUDE_PLUGIN_ROOT}` paths into the consumer repo.
