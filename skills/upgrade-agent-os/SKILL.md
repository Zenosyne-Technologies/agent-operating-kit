# Upgrade a Marvin (Agent Operating Kit) install

Current templates: `${CLAUDE_PLUGIN_ROOT}/templates/`. Never overwrite project-specific content — same merge discipline as install.

## Steps

1. **Detect installed state**: read `kit_version` from `.docs/PROJECT-INFO.md` frontmatter. No stamp? Fingerprint once: `docs/agents/` vs `.docs/agents/` location; `found-by:` present in taxonomy files (pre-registry); missing `label-syntax.md` / `tracker-config.md` / `planning-research.md` / `PROJECT-INFO.md`; list-style PROJECT-INFO without frontmatter. Report what was detected before changing anything.
2. **Diff by upgrade files**: read `${CLAUDE_PLUGIN_ROOT}/upgrades/` and apply, in semver order, every file AFTER the installed version up to and including the current one — each lists the consumer-visible steps; files stating "No consumer-visible changes" are skipped. Fall back to diffing against `${CLAUDE_PLUGIN_ROOT}/templates/` only where a step is ambiguous or the install predates version stamps (step 1 heuristics). Also track the label-registry delta (installed `label_syntax_version` → current registry H1).
3. **Migrate repo files** (no confirmation — git-revertible): `git mv docs/agents → .docs/agents` where applicable and rewrite CLAUDE.md references; add missing cascade files INCLUDING the selected tracker's `tracker-config.md` and `stats-collection-brief.md` (from `${CLAUDE_PLUGIN_ROOT}/templates/pm/<tracker>/`, installed to `.docs/agents/`), and the three `.docs/handbooks/<audience>/INDEX.md` skeletons where missing, with placeholders resolved, and `.docs/marvin/MEMORY.md` where missing; remove kit-installed persona copies from `.claude/agents/` where present (the seven v0.18.0 files — developer, developer-small, validator-completion, validator-security, researcher, documenter, ponytail — now ship WITH the plugin as `marvin:*` agents; only delete files whose content matches the kit's, never a project's own agent); merge CLAUDE.md rule updates without touching project rules; convert a legacy PROJECT-INFO to frontmatter form per the `project-info` skill. Autocommit (attribution per project settings).
4. **Sync tracker structure**: re-dispatch the installed tool's intake brief (idempotent — linear, jira, github, local; sources under `${CLAUDE_PLUGIN_ROOT}/templates/pm/<tracker>/`) as a sub-agent to seed new labels and refresh the guide. Skip when `pm_tool: none` (legacy); `local` dispatches its brief like any other tool. A `none` install may adopt the Local tracker — offer it, and on yes set `pm_tool: local` + install the local tracker files and dispatch its brief (project-key flow per `${CLAUDE_PLUGIN_ROOT}/templates/pm/INSTALL.md`).
5. **Gated data migration**: if the registry delta includes supersessions (mappings in the registry changelog, e.g. `found-by:agent-qa → origin:agent-qa`, `found-by:owner → origin:architect-request`), query the tracker for the affected-issue count and ask ONE yes/no. Yes → dispatch a ponytail (micro-tier) relabel sweep with the mapping as prepared payload. No → report the pending sweep and mapping. Never sweep unasked.
6. **Restamp + report**: update `kit_version` (from `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`) and `label_syntax_version` in the frontmatter; commit. Report: from→to versions, files migrated, labels seeded (from the brief's machine message), sweep executed/pending/none, telemetry opt-in offered (when the token-telemetry plugin is present but `.claude/telemetry` is absent; when the plugin itself is absent — `claude plugin list` — advise installing it: `claude plugin install token-telemetry@emprove`, restart for hooks, with one line on the cost-aware features it adds; the restart rule ALSO applies when the upgrade enables telemetry — capture starts next session, say so), and — if Jira and the connector now supports release creation — that the `convert-milestones` brief is ready to dispatch.

## Rules

- Steps 1–4 and 6 run without confirmation; step 5 is the ONLY interactive gate (shared tracker state is not git-revertible).
- Re-running on a current install must be a clean no-op (report `already at <version>`).
- Installed files stay self-contained: never write `${CLAUDE_PLUGIN_ROOT}` paths into the consumer repo.
