# Upgrade a Marvin (Agent Operating Kit) install

Current templates: `${CLAUDE_PLUGIN_ROOT}/templates/`. Never overwrite project-specific content — same merge discipline as install.

## Steps

1. **Detect installed state**: read `kit_version` from `.marvin/PROJECT-INFO.md` frontmatter. No stamp? Read `.docs/PROJECT-INFO.md` (pre-v0.21.0 location) before concluding none exists. Fingerprint once: cascade at `docs/agents/` vs `.docs/agents/` vs `.marvin/agents/`; `found-by:` present in taxonomy files (pre-registry); missing `label-syntax.md` / `tracker-config.md` / `planning-research.md` / `PROJECT-INFO.md`; list-style PROJECT-INFO without frontmatter. Report what was detected before changing anything.
2. **Diff by upgrade files**: read `${CLAUDE_PLUGIN_ROOT}/upgrades/` and apply, in semver order, every file AFTER the installed version up to and including the current one — each lists the consumer-visible steps; files stating "No consumer-visible changes" are skipped. Fall back to diffing against `${CLAUDE_PLUGIN_ROOT}/templates/` only where a step is ambiguous or the install predates version stamps (step 1 heuristics). Also track the label-registry delta (installed `label_syntax_version` → current registry H1).
3. **v0.20.0 → v0.21.0 layout migration** (no confirmation — git-revertible ONLY under the mechanics below). Marvin's machinery leaves `.docs/` for `.marvin/`: the kit's own cascade files → `.marvin/agents/`, `.docs/PROJECT-INFO.md` → `.marvin/PROJECT-INFO.md`, `.docs/marvin/MEMORY.md` → `.marvin/MEMORY.md`, and per audience `.docs/handbooks/<audience>/INDEX.md` → `index.md`. `.docs/project-management/`, `.docs/reports/`, the handbook pages themselves and every consumer-authored file STAY — project record, not machinery. A pre-`.docs/` install migrates `docs/agents/` → `.marvin/agents/` in one hop. Then rewrite the stale references (scoped per rule 7). Commit with selective `git add` per rule 2. This step is **unattended authority over someone else's repository** — the § *Migration mechanics* rules below are what make that safe. Every one was earned by a reproduced failure; none is optional.
4. **Migrate remaining repo files** (no confirmation — git-revertible): add missing cascade files INCLUDING the selected tracker's `tracker-config.md` and `stats-collection-brief.md` (from `${CLAUDE_PLUGIN_ROOT}/templates/pm/<tracker>/`, installed to `.marvin/agents/`), and the three `.docs/handbooks/<audience>/index.md` skeletons where missing, with placeholders resolved, and `.marvin/MEMORY.md` where missing; remove kit-installed persona copies from `.claude/agents/` where present (the seven v0.18.0 files — developer, developer-small, validator-completion, validator-security, researcher, documenter, ponytail — now ship WITH the plugin as `marvin:*` agents; only delete files whose content matches the kit's, never a project's own agent); merge CLAUDE.md rule updates without touching project rules; convert a legacy PROJECT-INFO to frontmatter form per the `project-info` skill. Autocommit (attribution per project settings).
5. **Sync tracker structure**: re-dispatch the installed tool's intake brief (idempotent — linear, jira, github, local; sources under `${CLAUDE_PLUGIN_ROOT}/templates/pm/<tracker>/`) as a sub-agent to seed new labels and refresh the guide. Skip when `pm_tool: none` (legacy); `local` dispatches its brief like any other tool. A `none` install may adopt the Local tracker — offer it, and on yes set `pm_tool: local` + install the local tracker files and dispatch its brief (project-key flow per `${CLAUDE_PLUGIN_ROOT}/templates/pm/INSTALL.md`).
6. **Gated data migration**: if the registry delta includes supersessions (mappings in the registry changelog, e.g. `found-by:agent-qa → origin:agent-qa`, `found-by:owner → origin:architect-request`), query the tracker for the affected-issue count and ask ONE yes/no. Yes → dispatch a ponytail (micro-tier) relabel sweep with the mapping as prepared payload. No → report the pending sweep and mapping. Never sweep unasked.
7. **Restamp + report**: update `kit_version` (from `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`) and `label_syntax_version` in the frontmatter; commit. Report: from→to versions, files migrated, **every file the migration DECLINED to move (consumer-owned) and every destination collision, each named in full**, labels seeded (from the brief's machine message), sweep executed/pending/none, telemetry opt-in offered (when the token-telemetry plugin is present but `.claude/telemetry` is absent; when the plugin itself is absent — `claude plugin list` — advise installing it: `claude plugin install token-telemetry@emprove`, restart for hooks, with one line on the cost-aware features it adds; the restart rule ALSO applies when the upgrade enables telemetry — capture starts next session, say so), and — if Jira and the connector now supports release creation — that the `convert-milestones` brief is ready to dispatch.

## Migration mechanics (step 3)

Transcribe these literally. Each exists because its absence was reproduced destroying consumer data or half-finishing a migration.

1. **Refuse to start on a dirty tree.** `git status --porcelain` must be empty BEFORE the first move. "git-revertible" — the justification for running this unattended — is FALSE on a dirty tree: the consumer's WIP lands in the migration commit and their later `git revert` destroys it. If dirty: STOP, print `git status --short`, tell the user to commit or stash themselves. **Never stash on their behalf** — a stash you create is a stash they don't know to pop.
2. **Selective `git add` only. `git add -A` is FORBIDDEN here.** Stage exactly the paths you moved (old and new), by name. `git add -A` sweeps untracked consumer files into the migration commit — a fixture caught it staging `.env.local`. Rules 1 and 2 hold together: break either and the revert escape hatch this step advertises stops working.
3. **Move the kit's OWN files, never the consumer's.** `.docs/agents/` may hold consumer-authored files (a runbook, project notes). Move file-by-file against the kit's known cascade set — `briefing`, `documentation-agent`, `handbooks`, `label-syntax`, `planning-research`, `ponytail`, `reporting`, `security`, `stats-collection-brief`, `ticket-filing`, `token-economics`, `tracker-config`, `validation-agent` (`.md`) — never `git mv` the whole directory. Anything else stays put, and the step-7 report must NAME every file it declined to move. `rmdir` the source only if it ended up empty.
4. **Create the exact destination directories first** (`mkdir -p .marvin .marvin/agents`). `git mv` creates no parent; `mkdir -p .marvin` alone is not enough for the per-file moves and every one dies `fatal: … No such file or directory`.
5. **Destination checks: index AND disk for real paths; index ONLY for the case-only rename.** These differ and the distinction is the whole point. For a *real* move, treat a destination as occupied if `git ls-files --error-unmatch <dst>` succeeds **or** `[ -e <dst> ]` — a consumer who hand-migrated with `cp`/`mv` (or whose `.marvin/` is gitignored) leaves an untracked destination that an index-only guard walks straight past, and `git mv` then NESTS into `.marvin/agents/agents/`. For the *case-only* handbook rename the disk test must NOT be used: `INDEX.md` and `index.md` are the same inode on case-insensitive filesystems, so `[ -e … ]` is already true before the rename and would skip it silently, shipping `INDEX.md` and breaking case-sensitive checkouts. Verify all results with `git ls-files`, never `ls` — `ls` prints the old casing.
6. **On collision, report and stop that step — never delete.** Name both paths, say they must be reconciled by hand, continue the remaining steps, and surface it in the step-7 report. **You never run `git rm -r`, `rm -rf`, or any recursive delete during a migration** — not on either side of a collision, not to "clean up". Reconciling is the user's call on their own data.
7. **Scope the reference rewrite; `INDEX.md` → `index.md` ONLY on handbook paths.** Rewrite `.docs/agents/`, `.docs/PROJECT-INFO.md` and `.docs/marvin/` freely, but lowercase `INDEX.md` only where it is part of a `.docs/handbooks/…` path. A blanket pass corrupts a Local-tracker install: `tracker-config.md` carries bare `INDEX.md` references to `.docs/project-management/INDEX.md`, which stays uppercase — lowercase it and the filing agent finds no index, creates one at `next_issue: 1`, and starts overwriting existing issue files.
8. **`__index.tmp` is a RESUME MARKER, not garbage.** The case-only rename is two `git mv` calls via a temp name. If a run dies between them the source guard is off forever and only the temp file survives — skipping it loses the handbook index permanently. Check the temp name FIRST: if `.docs/handbooks/<audience>/__index.tmp` is tracked, complete the rename from it; only otherwise start from `INDEX.md`.
9. **`rmdir .docs/marvin` is BEST EFFORT.** A consumer may keep their own files there; `rmdir` then exits 1 and, transcribed into a `set -e` script, aborts the run before the handbook renames. Remove it only if now empty, never let it fail the run, never delete a non-empty directory.

Guarded this way the step is **idempotent and resumable**: a second run performs 0 moves, leaves `git status --short` empty and HEAD unchanged.

## Rules

- Steps 1–5 and 7 run without confirmation; step 6 is the ONLY interactive gate (shared tracker state is not git-revertible).
- Re-running on a current install must be a clean no-op (report `already at <version>`).
- Installed files stay self-contained: never write `${CLAUDE_PLUGIN_ROOT}` paths into the consumer repo.
